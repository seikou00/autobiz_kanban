# Plan v2 阶段阻断规则

Plan v2 只拦会破坏工作流调度或覆盖计算的机器事实。机器校验不按任务大小、拆分理由措辞、文件预测、方法预测或测试命令阻断。语义回检仍应修正有证据的过大任务和机械碎片化，不能把“没有数量门槛”理解成任意打包。

## 当前规则

| 规则码 | 为什么必须阻断 | 回归测试 |
|---|---|---|
| `invalid_plan_task_scenario_reference` | 覆盖计算按 `spec 路径#SCN-NNN` 精确归集。区间、多个 ID 或裸 ID 会让未实现的场景被误判为已覆盖。 | `test_range_reference_creates_false_scenario_coverage` |

引用存在性、需求/场景覆盖、设计 ID、仓库绑定和 DAG 由各自的结构校验处理。它们直接关系到能否启动正确的任务，仍是 blocker。

## 已移除的 Plan 限制

- SCN / API / Page / UIX 的数量上限；
- 合并或拆分理由的长度、措辞和 ID 数量要求；
- 预先声明文件、符号、写集和实现步骤；
- 预先声明测试资产、测试命令和命令目录；
- 由数组顺序推导的前后端或 Batch 车道限制。

隔离工作树按依赖和仓库归属乐观调度；真实冲突由 Merge Train 处理。并发任务写入范围未知时，受影响的测试和质量证据会保守失效，确保后续验证不会错误复用。
