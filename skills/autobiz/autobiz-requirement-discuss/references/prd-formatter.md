# PRD 格式化技能

根据用户上传的原需求，按照模板格式重写需求文档。

使用任何 `request_user_input` 前，必须先读取并遵循 `${pluginPath}/skills/references/ask-user-question.md`。

## 工作流程

### 步骤1：读取原需求文档

读取用户提供的原需求文档内容。

### 步骤2：读取模板文档

读取 `{pluginPath}/skills/autobiz/autobiz-requirement-discuss/references/prd_module.md` 模板文档，了解改写格式要求。

### 步骤3：分析原文档结构

分析原需求文档的内容结构，识别其包含的章节和内容类型（如背景说明、角色定义、功能描述、验收标准等）。**注意：模板文档的章节结构可能动态调整，应基于实际读取的模板内容而非硬编码的章节列表进行分析。**

### 步骤4：按模板重写文档

按照 `{pluginPath}/skills/autobiz/autobiz-requirement-discuss/references/prd_module.md` 模板格式，将原需求文档内容填充到对应章节。

**子步骤说明：**

#### 4.1 询问用户选择方案设计类型

使用 `request_user_input` 询问用户选择方案设计类型：

**问题ID**: design_type
**问题**: 请选择方案设计类型
**选项**:
1. 用户故事地图 - 适用于复杂产品需求梳理，通过地图避免遗漏关键模块，并产出版本发布计划
2. 流程图 - 适用于步骤明确的流程，将复杂流程简化、逻辑清晰化

先根据原需求判断更适合的类型，将该选项放第一位并在 label 末尾标记 ` (Recommended)`；不得固定推荐某一种类型。

#### 4.2 生成用户旅程图

根据原需求文档的内容，分析并生成用户旅程图，包含：
- 用户角色：基于原文档中涉及的岗位
- 旅程阶段：基于原文档的核心交付和功能流程
- 触点：用户与系统交互的具体环节
- 用户行为：在每个阶段的具体操作
- 痛点与机会点：从原文档中提取的改进点

#### 4.3 填充模板各章节

将原需求文档内容按模板章节结构逐项填充。

**重要规则：**
- 功能清单必须详尽完善，必须包含原始文档中属于该特性的所有内容，包括所有表格、列表、验收标准等
- 不遗漏原需求文档中的任何细节
- 保持原有内容的完整性
- **生成的新PRD中禁止包含模板文档的注释说明内容**（如"> 1. **描述**：..."、"> 2. **核心要素**：..."、"> 3. **适用场景**：..."、"> 4. **局限性**：..."等模板编写说明）
- 只保留模板的章节结构框架，具体的填写内容应基于原文档分析得出

### 步骤5：询问用户确认

在重写过程中，如果遇到以下情况，使用 `request_user_input` 询问用户：
- 原文档内容不完整，缺少必要信息
- 某些功能描述模糊，无法确定具体实现方式
- 缺少必要的验收标准
- 模板中某些字段在原文档中找不到对应内容
- 需要用户确认某些业务逻辑


## 模板章节说明

**注意：以下章节结构基于当前模板文件 `{pluginPath}/skills/autobiz/autobiz-requirement-discuss/references/prd_module.md` 的内容。模板可能动态更新，实际重写时应以模板文件的最新内容为准，不要在生成的新PRD中包含模板的注释说明。**

当前模板包含以下章节结构：


**需求摘要**

1. **需求概述**
- 1.1 背景、痛点、改进思路及价值（必填）
- 1.2 用户角色表（必填）
- 1.3 术语名词解释（选填）
- 1.4 价值衡量指标（选填）

2. **需求解析**
- 2.1 用户现状（必填，含用户旅程图）
- 2.2 方案设计（用户选择：用户故事地图 或 流程图）
- 2.3 状态图（选填）
- 2.4 角色与权限矩阵（选填）
- 2.5 原型设计图（选填）
- 2.6 功能清单（必填）
  - 2.6.1 功能详情（每个功能FR1、FR2...）

## 注意事项

- 功能清单是必填项，必须完整包含原文档中的所有功能点
- 每个功能需要包含功能概述和验收标准
- 验收标准需要详细完整，不遗漏原需求文档中的任何细节
- 生成的新PRD中禁止包含模板的注释说明，只保留章节结构和实际业务内容
- 用户旅程图必须根据原文档内容生成，不能留空或复制模板注释
- 方案设计必须先询问用户选择类型，再根据选择生成对应内容
