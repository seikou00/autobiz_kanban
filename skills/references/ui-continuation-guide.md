# 阶段完成后的续办引导

## 适用时机

仅在当前技能已经完成、产物校验通过，并且 checkpoint 已更新到完成态后使用本规则。

如果当前技能仍在执行、正在等待用户确认、存在未完成任务或校验尚未通过，用户输入“继续”时应继续处理当前技能，不要引导用户离开当前对话。

当阶段已经完成，用户又输入以下含义的内容时，视为希望推进下一阶段：

- 继续
- 下一步
- 继续推进
- 开始下一阶段
- 接着做
- 往下进行
- 其他语义相近的表达

用户表达续办意图，不代表可以在当前对话中直接调用下一个技能。先读取当前 Feature 的真实状态，再告诉用户应该如何从项目 UI 继续。

用户已经通过“继续”等表达明确了续办意图，不要再次询问“是否继续”或要求用户重复确认。此时应直接计算下一步并给出 UI 引导。

## 计算下一步

执行以下命令：

```bash
python "${pluginPath}/hooks/resolve_next_skill.py" \
  --workspace "${pluginWorkspace}/${projectDir}" \
  --feature "${feature}" \
  --json
```

始终以脚本返回的 checkpoint 和路由结果为准，不要根据之前的对话、静态流程说明或记忆猜测下一阶段。

不要通过读取 `/autobiz`、`/autodev`、`/autoops` 或其他父级、根级 `SKILL.md` 来推断下一步。父级技能只描述编排原则，不能替代当前 Feature 的动态路由结果。

## 正常续办

当脚本返回正常的下一阶段时，优先使用 `nextAction.dialogTips` 向用户说明下一步；如果没有可用说明，再根据 `recommendedNextSkill` 概括下一阶段。

回复保持自然、简短，不要求用户记住或手动输入技能名称。可以使用下面的表达：

> 当前阶段已经完成，下一步是「{下一阶段说明}」。  
> 请回到项目 UI，打开当前 Feature，根据看板上的下一步提示新建对话。UI 会自动带入正确的技能和上下文，这个对话先停在这里。

不得在当前对话中直接调用 `recommendedNextSkill`，也不得继续执行下一阶段。

## 需要用户选择

如果返回 `requiresProfileChoice: true`，说明进入下一阶段前还需要选择工作流路线。提示用户：

> 当前阶段已经完成。接下来需要先选择后续工作流路线，请回到项目 UI，打开当前 Feature，根据看板提示完成路线选择并新建下一步对话。

如果返回 `requiresWorkflowChoice: true`，说明需要决定是否启用某个可选阶段。提示用户：

> 当前阶段已经完成。下一步包含一个可选阶段，请回到项目 UI，打开当前 Feature，根据看板提示完成选择并新建下一步对话。

不要在当前对话中替用户默认选择，也不要绕过选择直接进入某个技能。

## 阻断与终态

如果 checkpoint 为 `needs_fix`，提示用户：

> 当前 Feature 还有需要处理的问题，暂时不能直接进入下一阶段。请回到项目 UI 查看阻断节点和相关报告，再根据看板提示选择回流阶段并新建修复对话。

如果 checkpoint 为 `archived`，提示用户：

> 当前 Feature 已经归档，流程已全部结束，不需要再创建下一步对话。

如果脚本返回 `ok: false`，简要展示错误并提示用户：

> 暂时无法确认下一步，当前 Feature 的流程状态可能需要处理。请回到项目 UI 检查状态或阻断信息，修复后再从看板继续。

脚本失败时不得猜测下一技能，不得根据正常流程强行推进。
