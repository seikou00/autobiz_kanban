# 提问参考

需求澄清 / 讨论时怎么提问：把用户模糊的想法帮他磨清晰，是**协作思考**，不是需求登记，也不是审问。提问贯穿澄清全程——开口前和追问中都对照，不是问完再回看。

## 心态：思考伙伴，不是审问者

用户脑子里往往只有一个模糊的想法，你的活儿是帮他磨锋利。好问题让他「啊，这个我没想到」或「对，我就是这个意思」。别照脚本走、顺着线索走；别审问、一起想。

## 怎么问

- **开放开场**——先让他把脑子里的模型倒出来，别急着上结构打断。
- **顺着能量走**——他强调什么、什么让他兴奋、哪个痛点点着了这件事，就往哪儿挖。
- **追问模糊**——绝不接受含糊词。「好」是多好？「用户」是谁？「简单」是简单到什么程度？
- **把抽象具体化**——「带我走一遍怎么用」「那实际长什么样」「给个例子」。
- **澄清歧义**——「你说 Z，是指 A 还是 B？」「你提到 X——多讲讲。」
- **知道何时停**——当你说得清他要什么、为什么、给谁、完成长什么样，就收，并提议进入下一步。

## 问题类型（按线索挑，不是清单）

- **动机 / 为什么存在**：「什么促成了这件事？」「现在你用什么顶替它？」「有了它你会怎么做？」
- **具体 / 到底是什么**：「带我走一遍」「你说的 X 实际长什么样」「举个例子」。
- **澄清 / 到底指什么**：「你说 Z，是 A 还是 B？」「你提到 X——多讲讲。」
- **成功 / 怎么算成了**：「你怎么知道它成了？」「完成长什么样？」

## 用选项式提问帮用户思考

用选项式提问工具（ `request_user_input`）给用户具体的东西去反应，比空问更能帮他想清楚。

- **好选项**：对他意思的几种解读、可确认 / 否认的具体例子、能暴露优先级的具体取舍。
- **坏选项**：泛类目（「技术 / 业务 / 其他」）、预设答案的诱导项、太多项（2–4 个最好）。

```
含糊回答「它要快」 → 问「快在哪？」   选项：亚秒响应 / 扛大数据量 / 开发快 / 我来说
提到「现有工具让我烦」 → 问「具体烦什么？」 选项：点太多下 / 缺功能 / 不稳 / 我来说
```

## 自由表达规则

**当用户想自己讲，停用选项式提问。** 他选了「其他」并示意要用自己的话描述（「我来说」「让我讲讲」，或任何开放式、非选项的回复）时：改用纯文本追问，等他在正常输入处敲字，处理完他的自由回复再恢复选项式提问。别把「我来说」又塞回一组新选项里。

## 背景清单

- 做什么（具体到能讲给陌生人听）
- 为什么要存在（驱动它的问题或渴望）
- 给谁用（哪怕只是自己）
- 完成长什么样（可观察的结果）

四样。他主动多给的，一并收下。

## 反模式

清单式走过场（不管他说了啥都过一遍维度）· 罐头问题（「你的核心价值是什么」不看语境）· 官腔（「你的成功标准 / 干系人是」）· 连环炮（只发问不接话）· 赶进度（草草问完好开工）· 浅接受（含糊答案不追）· 过早约束（还没懂想法就问技术栈）· 别问用户的技术水平（活儿你来干）。
