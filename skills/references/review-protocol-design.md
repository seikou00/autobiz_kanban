# 按需独立审查 · dev.design

仅在用户要求或存在破坏性接口、数据迁移、跨仓协议等高风险变更时使用。常规设计由主会话自检。

向 `critic-autodev-design-zh` 提供 feature 目录的绝对路径、proposal、相关 specs、design.md、实现范围，以及本轮风险或待核对问题；已有资料与证据直接复用。

审查只判断行为覆盖、关键方案、验证思路与引用代码事实；机器已负责的格式和引用解析不重复报告。兼容精简与旧版设计，只打开设计实际引用的代码锚点，不补做全仓探索。

每个问题给出具体证据、影响和建议；没有问题直接说明。无需固定分节、严重度词表或分类台账。

主会话核实成立的问题后批量修复；真实取舍按共享提问协议处理，上游行为问题回写 Specs。产物发生变化后刷新契约锁并校验，完成仍通过原 `design_done` Human Gate。
