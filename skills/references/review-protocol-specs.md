# 行为规格回检 · dev.specs

对照 PRD 或用户需求、相关资料快照、已确认结论及现有代码，阅读 proposal 与全部 specs。

重点检查：

- 需求涉及的角色、主流程、异常和权限分支是否有验收场景承接，是否存在遗漏或矛盾。
- 行为是否符合本轮实现范围和 UI 上下文，是否混入技术方案或范围外工作。
- 外部资料中的相关行为约束是否已被吸收；不要求固定来源映射表。
- 影响行为或验收的未知事项是否已澄清，不以表格里的“已确认”代替用户答复。

发现明确遗漏或错误时修正对应行为，保持既有 REQ/SCN 稳定；需要取舍或与已确认需求冲突时交用户裁定。仅有措辞偏好不阻断完成，不为消除问题而删减需求范围。

可直接检查，也可在需要独立视角且工具可用时委派回检。结论简要汇报即可，不要求独立报告、固定结论表或审查状态词。修正后检查受影响行为，不强制重新派发整轮回检。

文档结构和引用由完成状态更新时的校验负责。按校验返回的定位修复当前产物；需要用户裁定或上游调整时说明问题，不重复维护一套格式规则。
