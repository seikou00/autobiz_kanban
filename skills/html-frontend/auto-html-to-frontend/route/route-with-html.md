# 含 HTML 路线

## 1. 这条路线什么时候使用

当满足任一条件时，使用本路线：

| 输入 | 处理 |
| --- | --- |
| 用户上传 `.html` / `.htm` 文件 | 走本路线 |
| 用户直接粘贴 HTML 内容 | 走本路线 |
| 用户提供的设计产物已经能导出或拿到实际 HTML | 走本路线 |

当满足以下条件时，不走本路线：

| 输入 | 处理 |
| --- | --- |
| 只有截图 / 图片，没有 HTML | 停下并要求用户补 HTML |
| 只有 Figma / 设计链接，但拿不到实际 HTML | 停下并要求用户补 HTML |
| 只有 HTML URL，但最终拿不到实际内容 | 停下并要求用户补 HTML 文件或内容 |

## 2. 这条路线只负责什么

本文件只负责：总原则、读取顺序、转交给 `html-parser.md` 的时机、失败兜底。不展开实现细则，不替代 `SKILL.md` 的全局优先级，也不重复 `html-parser.md` 的执行规则。

## 3. 路线总原则

### 3.1 HTML 是视觉契约

只要用户已经提供高保真 HTML：

- 表现层样式以高保真还原为准
- 不再强要求字体、字号、字色、背景色、边框、边框色、`border-radius` 等去对齐 token
- design system / token 只用于 HTML 没给出的交互态和默认组件细节

### 3.2 先整页恢复，再局部组件化

本路线统一使用两阶段心智：

| 阶段 | 目标 |
| --- | --- |
| Stage 1 | 先恢复整页视觉与结构 |
| Stage 2 | 再替换已经证明安全的组件槽位 |

### 3.3 有高保真时，不为“工程化”主动改视觉

不要为了更像 design system / AntD 默认样式 / 更整齐 / 更像某个已有页面，就改掉高保真里已经明确给出的视觉结果。

## 4. 默认读取顺序

进入本路线后，默认按这个顺序工作：

1. 读取 HTML 来源
2. 运行 `scripts/prepare_html_analysis.py`
3. 读取：
   - `output/html-analysis/<task>.md`
   - 原始高保真 HTML
4. 读取项目 `architecture/` 文档、当前目标文件，以及按可用情况补充 `prd.md` / 接口说明文档
5. 把任务转交给 `deps/html-parser.md`
6. 最终做遗漏回检

## 5. 转交规则

执行完上面的第 4 步后，默认直接转交：

- 目标文件：`deps/html-parser.md`
- 默认入口：从 `§3 分类 HTML` 开始

转交时附带的上下文应包含：

- 原始 HTML
- `output/html-analysis/<task>.md`
- 若有需要，再补：
  - 项目 `architecture/` 文档
  - 当前目标文件
  - 当前工作区 `prd.md`
  - 当前工作区接口说明文档

## 6. 本路线下的 HTML 类型观念

这条路线认可多种 HTML 来源，但**类型判断本身只是为了帮助 `html-parser.md` 选处理策略**，不在这里展开全部细则。

常见类型：

| 类型 | 用途 |
| --- | --- |
| 内联 style 高保真 | 常见于设计稿导出、局部高保真卡片 |
| utility class / Tailwind 高保真 | 常见于工程化静态页或复刻稿 |
| 纯 div / Figma / 绝对定位导出 | 常见于设计工具直接导出 |
| 原生语义 HTML | 常见于手写结构页 |
| 框架 / 组件 HTML | 常见于已有 React/Vue 片段 |

具体识别和处理细则，统一交给 `deps/html-parser.md`。

## 7. 增量修改

如果项目里已经存在目标页面：

1. 先读取当前页面文件
2. 以高保真 HTML 对比差异
3. 只改变化部分
4. 保留原文件中无关的逻辑、导入和状态管理

## 8. 失败兜底

### 8.1 URL 拿不到实际 HTML

如果来源是 URL，但拿不到真实 HTML：

- 停下
- 让用户补：
  - 直接粘贴 HTML
  - 上传 `.html`

### 8.2 `prepare_html_analysis.py` 不可用

如果脚本不可用：

- 跳过脚本
- 直接读取原始 HTML
- 继续转交给 `deps/html-parser.md`
- 最终说明：
  - `Stage 1 handoff: skipped`
  - 原因：脚本不可用 / 环境异常 / 文件异常

## 9. 和其它文件的边界

| 文件 | 一句话职责 |
| --- | --- |
| `SKILL.md` | 选路 + 全局优先级与执行清单 |
| `route-with-html.md` | 讲这条路怎么走（读取顺序、转交、兜底） |
| `deps/html-parser.md` | 真正把路走完（分类、整页恢复、组件替换、写代码） |
