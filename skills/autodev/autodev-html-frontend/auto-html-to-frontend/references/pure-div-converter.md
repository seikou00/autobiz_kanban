# 纯 div 补充规则

这份文件不是默认入口。

先读 `pure-div-core.md`，只有在以下情况出现时才升级到这里：

- 大体积绝对定位 HTML 的坐标关系不稳
- Tab / 左右栏归属判断容易出错
- 背景色被挂错元素或父子层级丢失
- 必填 `*` 重复、丢失，或字段名被过度发挥
- 组件接管后 raw layer 残留、重叠、溢出

## 适用输入

- 纯原生 div：几乎所有节点都是 `<div>`
- Figma / MasterGo 高保真导出：大量 `position:absolute`、`left/top` 坐标、设计工具生成痕迹

## 最小工作流

1. 大体积绝对定位页面先运行：

```bash
python scripts/analyze_absolute_html.py "<html-file>" --project-root "<project-root>" --out-dir output/html-analysis --output-name task-{N}
```

2. 以 `output/html-analysis/task-{N}.md` 作为主 handoff，只在需要时回查原始 HTML。
3. 先保留视觉基准，再做组件槽位替换。
4. 修正只能发生在组件槽位内部，不得重排外层 section、左右栏、顶部栏、底部操作区。

## 失败案例 1：背景归属

高频错误：

- 把背景色写到 `::after`
- 只保留子元素背景，丢掉父容器背景
- 把父容器背景错误地并到子元素上

正确规则：

- 背景色必须挂在实际拥有该背景的元素上，不放到伪元素。
- 父子元素如果都有背景色，两个层级都必须保留。
- 标题块、卡片块、section 块的背景和 padding 要跟原层级绑定，不要跨层挪动。

最小自检：

```text
[ ] 父容器背景还在
[ ] 子容器背景还在
[ ] 背景没有写到伪元素
[ ] 背景层级没有跨节点错位
```

## 失败案例 2：必填星号与字段名

高频错误：

- `label` 里保留 `*`，同时又给 `Form.Item` 加 `required`
- 看到 `required` 后把 label 文字丢掉
- 把 `prd.md` 里的字段名改写成“关键人职位”这类自作扩展

正确规则：

- 必填星号只保留一次。
- 如果文本以 `*` 开头，先去掉 `*`，剩余文字作为 label，再补 `required`。
- `label` 文字必须保留，不能只剩 `required`。
- 字段名称必须一比一还原 `prd.md`，不要增删限定词，不要改业务含义。

最小自检：

```text
[ ] label 文字还在
[ ] required 还在
[ ] label 里没有多余的 *
[ ] 字段名与 prd.md 一致
```

## 失败案例 3：坐标分栏与 Tab 边界

高频错误：

- 把子容器内部的 `left` 分割点当成顶层左右分割点
- 只看 DOM 嵌套，不看视觉坐标
- 把本应位于同一 `TabPane` 内的左右列拆成“Tab 内左边 + Tab 外右边”

核心规则：

### A. 先区分坐标层级

- 根容器直接子元素的 `left/top` 才能直接用于顶层分栏判断。
- 子容器内部元素的 `left/top` 是相对父容器的偏移，不能直接当画布级分割点。

### B. 顶层分割点和内部分割点分开算

- 顶层分割点：来自同一父容器下的左右两个大块容器。
- 内部分割点：来自某个 panel / tab 内容区内部的左右列。
- 如果某个较大的 `left` 值仍落在父容器范围内，它是内部分割点，不是顶层分割点。

### C. Tab Bar 宽度决定 Tab 覆盖范围

- `Tab Bar.width` 接近父容器宽度时，通常表示 Tab 内容横跨整个父容器。
- 这时 Tab 内部的左右列仍然属于同一个 `TabPane`，不是“Tab 左边内容 + 外部独立右栏”。

最小输出格式：

```text
【坐标判断结果】
根容器：left=__ top=__ w=__ h=__
顶层左面板：left=__ w=__
顶层右面板：left=__ w=__
顶层分割点：__px

Tab Bar（若有）：top=__ w=__
Tab 内容区（若有）：top=__
Tab 内左列：left __ ~ __
Tab 内右列：left __ ~ __
内部分割点：__px
```

最小自检：

```text
[ ] 顶层分割点来自顶层同级容器
[ ] 内部分割点没有被误提成顶层分割点
[ ] Tab 内左右列仍在同一个 TabPane 中
[ ] 右栏内容没有被塞进左栏卡片
```

## 失败案例 4：组件接管后的 raw layer 抑制

高频错误：

- 组件已经接管区域，但原始文本、假控件、占位框还留在原处
- 组件渲染后，原始层文本溢出到区域边界外
- 局部替换时把周围视觉盒子一并误删

正确规则：

- 某个区域由组件接管后，抑制该区域内的原始文本节点、placeholder、假控件和重复装饰。
- 只抑制被接管的槽位；未接管区域继续保留原视觉盒子。
- 如果组件后方确实需要背景块或分割线，可以保留装饰层；否则删除重复层。
- 组件替换后，若原始层文本仍溢出到区域外，视为失败，必须回退或重抑制。

最小自检：

```text
[ ] 被组件接管的区域不再残留原始文本
[ ] 未接管区域的视觉盒子还在
[ ] 没有重复按钮、重复输入框、重复标题
[ ] 没有文本溢出到区域边界外
```

## 严格禁止

- 不要新增 HTML 或 `prd.md` 中不存在的 section、字段、按钮或辅助区块。
- 不要把整页改造成新的 Card / Grid / Tabs 页面骨架。
- 不要移动外层 shell、左右栏、顶部栏、底部操作区。
- 不要合并、拆分、重命名原字段。
- 不要因为用了组件，就顺手重排整页比例或层级。
