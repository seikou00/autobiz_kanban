# 前端性能检测

本文中提到的 `SKILL.md` 均指仓库根技能 `../../../SKILL.md`。

这是 `route/review` 下的性能回检子技能。

## 什么时候使用

当满足任一条件时，调用本子技能：

- 用户明确要求“检测前端性能”“前端性能检查”“性能代码扫描”“检查性能问题”“前端性能审计”
- 主线页面已生成，需要补做一轮静态性能规范扫描
- 回检阶段需要把“功能正确”之外的性能风险一起纳入复核

## 检测范围

重点覆盖以下性能编码风险：

- 定时器中直接触发 API 请求
- 资源使用后未显式清除
- 循环中注册定时器 / 事件 / WebSocket
- 高频事件未节流 / 防抖
- 组件卸载时未清理副作用
- 轮询缺少退避和可见性感知
- 相同参数 API 重复调用

## 输入

按需读取：

- 目标前端代码文件或目录
- 主线生成后的目标页面 / 组件 / hook / API helper 文件
- 若需要，可补读项目 `architecture/` 中与性能约束、轮询、请求层相关的说明

## 执行方式

当前 route 未内置性能扫描脚本，因此默认按本文规则做手工静态扫描：

1. 用 `rg` 搜索定时器、轮询、事件监听、WebSocket、请求调用、高频事件处理和副作用清理相关代码。
2. 读取命中的目标文件，按检测范围逐项判断是否存在性能风险。
3. 输出问题位置、风险等级、原因和修复建议。

如果后续在 `route/review/scripts/` 增加了实际扫描脚本，再按脚本说明执行；脚本不存在时不得调用虚构命令。

## 输出

输出应至少包含：

- 问题总数
- 按风险等级分组的结果
- 每个问题的规则 ID、位置、代码片段、问题描述
- 修复建议

推荐汇报格式：

```text
【前端性能回检结果】
范围：<files>
结论：通过 / 有问题需修复 / 通过但有建议优化
高风险：
- <问题>
中风险：
- <问题>
是否已修改：是 / 否
备注：<可选>
```

## 边界

- 本子技能只负责性能规范扫描，不替代功能性回检
- 若脚本尚未加入 `scripts/`，按本文手工静态扫描规则执行
- 功能正确性、高保真还原、组件选型问题仍由 `html-post-review.md` 等回检子技能负责
