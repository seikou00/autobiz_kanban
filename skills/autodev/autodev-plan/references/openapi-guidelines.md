# OpenAPI 生成约束

## 核心原则

- 契约先行：先定义接口行为，再谈实现
- 一致性优先：路径、命名、错误体、分页风格保持统一
- 边界清晰：只承诺外部可观察行为，不泄露实现细节
- 添加优先：尽量通过新增可选字段扩展契约，避免破坏式修改

## 命名建议

- REST 路径使用复数资源名词，如 `/api/orders`
- query / response 字段使用 `camelCase`
- 布尔字段使用 `is` / `has` / `can` 前缀
- 枚举值使用稳定的字符串集合；若已约定全大写枚举，则保持一致

## 响应约定

- 成功响应要与 PRD 的核心场景一一对应
- 失败响应至少覆盖验证失败、鉴权失败、权限不足、资源不存在、冲突、服务端异常
- 错误体尽量统一为机器可读 `code` + 人类可读 `message` 的结构

## 生成时避免

- 把数据库表结构原样暴露成 API schema
- 写入未经确认的内部字段、审计字段、调试字段
- 只写 happy path，不写错误响应和边界条件
- 一个能力点同时混用多种分页或错误格式

## 无 HTTP API 的标准表达

如果本轮需求没有 HTTP/REST 契约，输出空 `paths`，并写：

```yaml
x-auto-no-http-api: true
```
