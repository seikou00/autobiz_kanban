# 任务边界示例

一个 Task 对应同一仓库内完整的行为交付，只有不同独立交付结果或跨仓库工作才拆分。共享页面、接口、文件不构成合并理由，场景或断言数量不构成拆分门槛。

| 需求 | 划分 |
|---|---|
| 提交订单，含输入校验、保存、返回编号及失败处理 | 一个行为任务 |
| 同页查询、编辑、取消与导出订单 | 可独立交付，分别建任务 |
| 导出提交、后台生成、下载与过期管理 | 按实际独立子流程拆分，只连真实依赖 |
| 不同 Git 仓库的页面提交与后端接口 | 分开；依赖由是否需要对方交付决定 |
| 为提交订单增加 DTO、service、持久化适配器 | 留在提交订单任务内部 |

`D-NNN` 归负责其行为结果的主交付任务，公共函数按实际职责归属；协作任务引用 API/Data/Scenario，不重复占有 D。`refs.design` 可补充未在 api/data 中列出的 API/DATA 上下文，不放 D。

代码组织、必要文件和测试框架由后续阶段结合实现决定。已有公开 API 路径和业务字段可用于说明契约；本期范围按 IMPLEMENTATION_SCOPE 的 included/deferred 分区执行。
