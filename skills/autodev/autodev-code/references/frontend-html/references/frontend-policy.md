# 前端实现规则

仅前端 TASK 读取一次；同一执行上下文无需反复读取。任务行为以 Specs 为准，视觉以实际可读的原始 HTML/资源为准，工程接入以项目资料与真实源码为准，任务身份和写入时机遵循 Runtime。分析摘要与资源候选不能覆盖原稿。

## 组件来源优先级

先读项目 AGENTS.md 指定规则，再查 architecture/components、本地组件、已安装且真实使用过的组件库、相似页面。没有真实导出/用法证据时不强用组件。默认组件外观与原稿不一致时补 props/样式；先恢复整页，再做安全的局部组件化。布局稳定后再落实 Table、Tabs、Pagination、Modal 等成熟结构。

## 项目说明优先级

AGENTS.md → 相关项目说明 → 真实源码 → 本技能参考。复用现有框架、样式、资源目录、alias 和路由，不能只因示例使用 React、AntD 或 Tailwind 就把它们引入不同技术栈。只查当前任务相关证据，不重扫已知工程事实。

## 技术栈兜底

用户明确指定的框架优先，否则使用项目 package.json、文档和真实源码确认的框架。仅新页面/新工程且确无证据时，以 React 为候选；桌面优先已有 AntD，移动端优先已有 Ant Design Mobile。依赖不可用时用当前框架原生控件或记录能力缺口，不因兜底规则自动引入未安装的库。

## 图标来源顺序

项目图标规则 → 本地 icon/SVG/iconfont → 已安装且实际在用的库。真实图片、头像、Logo、未知 SVG 默认保留。只有视觉足够相近且依赖可用时才换成组件；不能凭文件名猜测后强制替换。纯图标按钮补可访问名称。源矢量若是占位几何而非真实资产，按周围语义推断真实内容，不能照搬占位符。

## 图表来源顺序

项目规则/图表封装 → 本地 chart → 已安装且实际在用的图库。sparkline、趋势线、漏斗也是图表，保持 series 数量、图例、颜色和相对位置。有真实数据/交互要求时不能用 CSS、横线、静态 SVG 或统计卡片假装图表。结构恢复阶段可暂时保留源图；最终交付须明确真实图表状态。

执行阶段不临时安装依赖；先用已有能力，缺关键能力记录准确缺口，交由准备/依赖流程按已有授权集中解决。不能把未完成图库接入写成非阻断的已完成图表。

## 视觉与布局

有 HTML 时保留其字体、字号、文案、间距、颜色、边框、圆角、阴影、方向、层级；token 只补未给出的状态。数字+单位、金额+币种不拆行。父级决定尺寸时子级优先伸缩/继承，避免层层写死宽高。整页视觉稳定后再替换组件，最后核对样式细节与关键区块完整度。

无高保真 HTML、部分页面没有稿件或来源暂不可读时，正常按 Specs、项目公共组件及相似页面实现，记录输入缺口；不因缺稿阻止写入，也不声称已完成与稿件的一比一还原。

## 验证与速度

统一回检由 frontend-route.md 指定的 frontend_verification.py 执行。复用同源码/输入/检查器的报告；不重复分析，不默认跑全量 build/lint/test。按需选择一个已有类型检查或构建脚本。页面检查使用平台内置 browser_* 工具；纯文本模型可检查 DOM 和文本。模型支持图像且平台实际提供截图工具时，使用当前 Batch 页面截图与原稿证据。禁止为本流程搜索外部 Playwright、检查全局浏览器缓存或安装浏览器依赖。

缺少多模态能力、浏览器环境或视觉核对结果时，保留视觉未验证的非阻断 advisory；静态与资产检查通过即可继续 finish-implementation，最终报告展示视觉缺口。已发现的视觉缺陷仍需修复，同轮定向处理最多两轮，修改后重验。具体命令、缓存和恢复见 frontend-route.md，不在各 parser 重复建立验证流程。
