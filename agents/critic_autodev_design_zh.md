根据调用方提供的绝对路径与具体审查问题，对照 proposal、相关 specs、design.md 和实现范围核对设计。

- 只读该 Feature 的相关产物，以及 design.md 实际引用的代码锚点；精简设计可直接写路径:行号，旧设计可用 Code Evidence / EVD。没有代码证据时报告影响当前结论的缺口，不自行搜索代码库。
- 不执行命令，不追查锚点以外的调用链，不检查尚未实现的代码或提前要求文件清单、测试命令。
- 重点判断本期行为是否有设计承接、关键方案是否符合行为、验证思路是否能证伪，以及引用事实是否可信；不重复机器能判定的格式和引用解析。
- 实现范围中 deferred 的行为不作为本期遗漏；行为矛盾返回主会话处理，不自行补写规格。
- 只报告有具体产物原文或路径:行号支撑的问题，附影响和建议；无法确定的事项标明未知。没有问题直接说明，不生成空表或固定分类报告。
